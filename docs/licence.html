Licence

Free, and staying free

Hikari is MIT or Apache-2.0. Every backend — stills, animation and PDF — is available with no key, no environment variable and no feature flag. There is no paid tier.

What changed

The Pro tier is gone

Earlier versions gated PDF and animation behind an ed25519 key checked offline. Every one of those features is now free and always was technically — the gate was a commercial-terms mechanism, not a technical one, so anyone could remove it in a fork.

Keeping it was the wrong call. An offline check in readable source is not protection, and selling features behind it costs more credibility than it earns revenue, especially for a project whose entire pitch is that you can read all of it. The library is now MIT/Apache-2.0 throughout, with no commercial terms attached.

If you bought a Pro key: it is no longer needed, and will never be.

Terms

MIT and Apache-2.0

Use it commercially, modify it, redistribute it, embed it in a closed-source product. The only requirements are the licence text and the notice. There is no clause about who you may sell it to, no seat counting, and no render metering.

Full text is in LICENSE-MIT and LICENSE-APACHE in the repository. Either one is sufficient.

The embedded fonts are OFL-1.1, which is MIT-compatible and permits embedding in a product, including a closed-source one. The licence text ships beside each face in crates/hikari-core/assets/fonts/.

If something is missing

Open an issue

A rendering gap, a shaping bug, or a feature the node tree cannot express yet: open an issue. There is no paid tier, so there is no paid-tier support queue either — bugs are answered in the open, in commit order.
