PNG encoder

The trade-off curve

Encoder settings trade bytes against time. The rejected rows are recorded so the choice is reproducible rather than asserted.

SettingBytesTime
tiny-skia default 117,7602.3 ms superseded
Best + Adaptive ~44,000~300 ms rejected — 100× slower for 1 KB
Default + Adaptive + RGB-strip 43,100~10.5 ms shipped
Fast + Adaptive 74,081~3.9 ms rejected — size

A filter-trial experiment, trying every filter at two levels, floors out around 44 KB on these pixels, so the remaining gap is content-side — gradient smoothness and anti-aliasing — not encoder-side. The trial was rejected: all cost, no gain.

Determinism

Same bytes, every platform

This is the property that makes golden-image testing possible for anyone downstream, so it is gated in CI. The expected digests live in crates/hikari/tests/determinism.sha256 and the render fails the build if it drifts.

TargetPNGSVG
macOS ARM64 21,649 B738 B
Linux x86_64 21,649 B738 B

These digests changed in v0.18, and the old ones were wrong. The embedded font subset was dropping GSUB, GPOS and GDEF, and the paint path was looking glyphs up by source character instead of by the id the shaper chose. Kerning and ligatures now actually apply, so glyph positions moved and the bytes moved with them.

Corrections

Where this document has been wrong

Kept deliberately. A benchmark document that has never been wrong has probably not been measuring anything.

v0.7
Claimed a large speed advantage. It came from a debug build with weak compression. Withdrawn; the numbers here are release numbers.
v0.13
Recorded a “kerning/ligature tradeoff” as an accepted cost of font subsetting. It was not a tradeoff — the subsetter was dropping the layout tables, so both were silently absent. Fixed in v0.18.
v0.18
Corrected the determinism digests, for the reason above.

Still to improve

Known weak spots

Cold start
14.3 ms against 3.69 ms warm. A smaller embedded font or a glyph cache shared across processes would help; neither is done.
Card output size
57,931 bytes is larger than the encoder curve suggests for a mostly flat image. Gradient banding is the suspected cause and it is unmeasured.
Coverage
One machine, one card. A real corpus would separate text-heavy, image-heavy and document workloads.

Full methodology, per-environment tables and the history behind each figure are in BENCHMARKS.md in the repository.
