Getting started

Install

No system dependencies. The only runtime requirement for correct text is Rust 1.78 or newer; the CJK fallback is optional.

rust 
cargo add hikari-rs

# or only the pieces you need:
cargo add hikari-rs-core hikari-rs-pdf
node 
npm i @hikari-rs/node

Prebuilt binaries cover macOS, Linux (glibc and musl) and Windows on x64 and ARM64. If your platform is not there, the napi CLI builds it from source in a few minutes.

First render

From Node.js

javascript 
const hikari = require('@hikari-rs/node');

const tree = JSON.stringify({
  Container: {
    style: { width: 1200, height: 630, background: '#0b1020' },
    children: [
      { Text: { text: 'Hello', style: { font_size: 84, color: '#ffffff' } } },
    ],
  },
});

require('node:fs').writeFileSync('og.png', hikari.renderPngSync(tree, 1200, 630));

Every style field is optional and colours take CSS strings. See the API page for the full shape.

Browser and edge

WebAssembly

javascript 
import init, { render_png, register_font } from './playground/pkg/hikari_wasm.js';

await init();

const png = render_png(JSON.stringify(tree), 1200, 630);   // Uint8Array

The dependency tree is pure Rust with no C zlib anywhere, so nothing needs a cross-compiled sysroot. The release build is about 2.8 MB. The playground is this build, running in this page.

Working on the engine

From source

shell 
git clone https://github.com/theoxfaber/hikari && cd hikari

cargo test --workspace --exclude hikari-rs-node   # 87 tests
cargo run -p hikari-rs --example card

# the Node binding needs Node's symbols, so it is tested through Node
cargo build --release -p hikari-rs-node
cp target/release/libhikari_node.dylib npm/hikari-node.node
node npm/test.mjs

Offline

No keys, no network

There is nothing to configure. Every backend — stills, animation and PDF — is available with no key material and no environment variable, and the library makes no network calls at any point. See Licence.
