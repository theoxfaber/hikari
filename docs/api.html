Reference

API

Everything renders from a node tree. There are three node kinds — Container, Text and Image — and every style field is optional. Try each one in the playground.

rust 
use hikari::{render_png, render_svg, render_webp, Node, Style};

let tree = Node::container(
    Style::centered()
        .with_size(1200.0, 630.0)
        .with_linear_gradient(180.0, &[(0.0, "#dbeafe"), (1.0, "#fee2e2")]),
    vec![Node::text("Hello", Style::text(84.0, "#0f172a"))],
);

std::fs::write("og.png", render_png(&tree, 1200, 630)?)?;

Fonts

Using your own typeface

Register once, then set the id on any node. It is inherited by descendants, so setting it on a card root covers every text run inside it — and layout, measurement, raster, SVG and PDF all resolve the same face, so text is never positioned for one font and drawn in another.

rust 
use hikari::register_font;

let brand = register_font("Inter", &std::fs::read("Inter-Regular.ttf")?)?;

// Ids are content-addressed: registering the same bytes again returns the
// same id and does no work, so this is safe to call per request.
let tree = Node::container(
    Style::row().with_size(1200.0, 630.0).with_font(brand),
    vec![Node::text("Shipped in your typeface", Style::text(72.0, "#fff"))],
);

Text helpers

Headline typography

Pure functions over shaped text. Layout and paint call the same code, so they agree exactly.

rust 
// Reflow to minimise the widest line, like CSS text-wrap: balance.
let balanced = balance_text(text, px, max_w, BUILTIN_FONT);

// Largest size at which the text still fits the box.
let size = fit_font_size(text, max_w, max_h, max_px, BUILTIN_FONT);

let (w, h) = measure_text(text, px, BUILTIN_FONT);

Documents and motion

PDF and animation

Both are free and take no key material. render_pdf_with takes document options; the animation encoders take frames with per-frame durations.

rust 
use hikari::{render_pdf_with, Attachment, PageSize, PdfOptions};

let options = PdfOptions {
    title: Some("Invoice".into()),
    paginate: true,          // flow one node across pages
    attachments: vec![Attachment {
        name: "factur-x.xml".into(),
        ..Attachment::new()
    }],
    ..PdfOptions::new()
};

let pdf = render_pdf_with(&[doc], PageSize::A4, &options)?;

let gif = render_animation_gif(&[(frame_a, 500), (frame_b, 500)], 480, 240)?;

A registered font id works in PDF too: fonts are embedded per document and the text stays selectable and extractable.

Front end

Write it in HTML and CSS

A card does not have to be a hand-built node tree. html_to_tree takes markup with an inline <style> block and returns a tree. Stylesheet plus from_elements takes a stylesheet and a declarative element tree instead, for callers who would rather build elements than write markup.

rust 
use hikari::css::{self, ParseReport};

let html = r#"
<style>
  .card { display: flex; flex-direction: column; justify-content: center;
          width: 1200px; height: 630px; padding: 80px;
          background: linear-gradient(180deg, #dbeafe, #fee2e2); }
  .title { font-size: 84px; color: #0f172a; }
</style>
<div class="card"><span class="title">Hikari</span></div>
"#;

let mut report = ParseReport::default();
let tree = css::html_to_tree(html, &mut report)?;

// Anything the subset does not implement is listed here rather than guessed,
// so a dropped declaration can never quietly render as the wrong thing.
println!("{report}");
let png = hikari::render_png(&tree, 1200, 630)?;

This is a subset, and it says so. Supported: box model, display, flex-direction, justify-content, align-items, gradients, colours in every common form, box-shadow, blend modes, background-clip: text, and text properties with CSS inheritance. Not supported: @media, custom properties, calc(), transform, z-index, masks and filters. Cascade is source order — documented rather than half-implemented.
